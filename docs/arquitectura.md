# MIDAZ architecture

> SAMPLE DATA. Describes what is in this repo today (Sprint 1). Items marked **(unverified)** are not yet tested.

## The idea in one line

Every sentence MIDAZ says that contains a number comes with a receipt: the SQL that produced it, the sources it read, and the data-quality warnings that applied. No receipt, no sentence.

## Components

> Naming: the product is MIDAZ, but the code folder is still named `midas/` (not renamed yet).

| Component | File(s) | Role |
|---|---|---|
| Data sources | `data/output/ventas_pos.csv`, `costos_inventario.csv`, `gastos_operativos.csv` | Three separate sources (POS, inventory, finance), generated by `data/generator.py` with a fixed seed |
| Semantic view | `sql/00_margen_por_producto.sql` | Joins sales and costs, removes VAT, flags `sin_costo` instead of using zero |
| Business queries | `sql/01`..`sql/30` | Data quality, 80/20, volume vs profit, monthly shortfall |
| Local engine | `midas/core.py` (`LocalEngine`) | SQLite stand-in: loads each CSV into its own schema (`pos`, `inventario`, `finanzas`) and runs the same SQL files |
| Federated engine | `midas/zetaris_client.py` | REST client for Zetaris; credentials only from environment variables **(unverified end to end)** |
| Answer builder | `midas/core.py` (`build_answer`) | Runs the queries and writes one claim + one receipt per sentence |
| Receipt format | `receipt/receipt.schema.json`, `receipt/example.json` | JSON Schema each receipt must satisfy |
| Control check | `midas/control.py` | Compares query results with the hand-check sheet `data/output/control_8020.*` |
| Entry point | `run.py` | `python run.py` / `test` / `check` |
| Language model | `midas/nightshift.py`, `midas/numguard.py` | NVIDIA Nemotron through Nightshift on a fixed lane (never `meterless/auto`) writes the sentences; `numguard` strikes any sentence whose numbers have no receipt. Built and tested with mocks; **not verified in Nightshift** |
| Quality rules | `midas/calidad.py` | Data-quality rules in code, checked against `sql/01_calidad_datos.sql` by `python run.py check` |
| Meterless Engine (H-MEM, HU-15) | `midas/memory.py`, `tests/test_hmem.py` | Python port of H-MEM, tested with the official conformance vectors |

## How a question is answered

1. Data quality runs first (`sql/01_calidad_datos.sql`). If products have sales but no cost, the first sentence is "No sé: N productos no tienen costo…".
2. The business queries run against the view.
3. Each sentence is built from a query result and gets a receipt (`R-NOSE`, `R-8020`, `R-80`, `R-TOP`, `R-VOL`, `R-MES`).
4. The answer text is exactly the joined claims; tests fail if any sentence lacks a receipt.
5. Results are checked against the control sheet; a mismatch makes `python run.py check` exit 1.

## Swapping the engine

The SQL is written once. `load_sql()` rewrites the two-part table names using `MIDAZ_SCHEMA_MAP` (for example `pos=<db>.<schema>`) so the same files can run on Zetaris. Dialect assumptions are listed in `sql/README.md` **(unverified on Zetaris)**.

## Not built or not verified yet

- Nightshift run: the Nemotron client is built and tested with mocks; not verified against Nemotron or Nightshift (Nightshift needs a Windows PC with a GPU). **Not verified.**

- Verifier step (`midas/verifier.py`): re-runs each receipt's SQL on the same engine, compares rows, checks the sentence's numbers; `verifier.verdict` = `confirmado` or `rechazado` (with `notes`); rejected sentences are replaced by "No sé". The Nemotron verifier call is still pending.
